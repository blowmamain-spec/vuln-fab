# Hasil M1 (Supabase + TypeScript)

Tanggal: lihat riwayat git. Versi: `0.1.0`. Detail per kelas: [`m1-lab.md`](m1-lab.md).

## 1. Lab `supabase-vuln` (ground truth berlabel)

| Metrik | Hasil | Gate |
|---|---|---|
| Recall (label dalam scope) | 25/25 = **100%** | ≥ 90% (tier A) |
| Precision (temuan ter-review) | **100%** (TP 25, FP 0) | ≥ 90% |
| Decoy terpicu | **0** (46 decoy) | 0 |
| Temuan tak berlabel | 0 | 0 |
| Waktu scan | ~0,4 dtk | < 10 dtk |
| Exception pada migration tak valid | tidak ada | tidak ada |

Kelas di luar scope (`business-idor`, tier C) tidak dilaporkan, sesuai rencana.

**Catatan jujur tentang angka ini.** Lab ditulis oleh pihak yang sama dengan pembuat rule, jadi
100% belum membuktikan akurasi pada kode orang lain. Angka ini adalah *gerbang regresi*, bukan
klaim akurasi. Klaim akurasi datang dari bagian 2.

## 2. Kode nyata: contoh resmi `supabase/supabase` (528 berkas, 1,7 dtk)

Tidak ada ground truth untuk repo ini, jadi hanya **precision** yang bisa dinilai (recall
tidak diketahui). Pemindaian pertama menghasilkan 82 temuan; peninjauan manual menemukan
kelas false positive yang kemudian diperbaiki dan dikunci dengan test regresi
(`tests/unit/test_supabase_realworld.py`):

| Temuan awal | Penyebab | Perbaikan |
|---|---|---|
| 7× `sb-policy-anon-write` | policy tanpa `TO` = `public`, tapi ekspresinya memanggil helper (`authorize()`, `is_project_member()`) yang menolak anon; evaluator `UNKNOWN` dianggap terbuka | `UNKNOWN` → confidence rendah |
| 7× `sb-config-signup` | `enable_confirmations = false` adalah bawaan `supabase init` untuk dev lokal | confidence rendah |
| 26× `sb-edge-no-jwt` | `verify_jwt = false` sering disengaja (webhook, endpoint publik) | medium hanya bila fungsi memakai service_role/DB; selain itu rendah |
| 2× `sb-grant-broad`, 2× `sb-default-priv` | boilerplate hasil `supabase db pull` (`FOR ROLE postgres`, `GRANT ALL` pada tabel ber-RLS) | confidence rendah |
| 1× `sb-policy-true` | `SELECT` publik pada tabel tanpa kolom pemilik ("public profiles") | confidence rendah |
| 2× `sb-dynamic-sql` | `format(%1$s)` dengan argumen bertipe `date` | argumen non-teks dianggap aman |
| 4× `sec-secret-hardcoded` | kunci demo publik Supabase (`iss: supabase-demo`) dan nilai terenkripsi dotenvx | dilewati |

Setelah perbaikan: **41 temuan tampil default** (35 lagi disembunyikan oleh ambang confidence):

| Rule | Jumlah | Penilaian |
|---|---:|---|
| sb-rls-missing | 14 | benar: tabel `public` tanpa RLS (demo: articles, countries, sales, ...) |
| sb-edge-no-jwt | 13 | benar: fungsi publik yang memakai klien admin (`supabaseAdmin`) atau DB |
| sb-storage-policy | 6 | benar: "Anyone can upload an avatar" tanpa cek pemilik |
| ts-table-no-rls | 4 | benar: kunci anon membaca tabel tanpa RLS |
| sb-definer-no-path | 3 | benar |
| js-innerhtml-assign | 1 | masuk akal (XSS lewat pesan realtime), belum diverifikasi dinamis |

Semua 41 dinilai sebagai kelemahan yang nyata; sebagian adalah **pilihan sengaja pada kode demo**
(mis. avatar bebas unggah), jadi "benar" di sini berarti klaim temuan itu faktual, bukan
bahwa contoh tersebut salah dibuat. Ini satu repositori kode contoh; sampelnya kecil dan bias
ke demo.

## 3. Yang belum terpenuhi untuk gate M1 penuh

- **WP-0.7**: aplikasi Supabase milik pemilik proyek belum dipindai (butuh migration privat).
  Contoh resmi dipakai sebagai pengganti sementara, bukan sebagai pengganti sebenarnya.
- Recall pada kode nyata tidak terukur (tidak ada ground truth untuk repo publik tersebut).
- Cross-check hanya melihat klien supabase-js dengan tabel bernama konstan; nama tabel dinamis
  dicatat sebagai `unresolved`, bukan ditebak.
- IDOR tier B untuk `.eq('id', x)` bergantung pada heuristik nama variabel (`params`, `req`, ...);
  penelusuran aliran data yang benar menunggu taint engine (Fase 5).
