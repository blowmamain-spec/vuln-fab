# D5 — Taint engine: build in-house vs. Semgrep backend

Status: **provisional, in-house continues** (decision point after WP-5.3).

## Evidence after WP-5.3 (intra-function)

- TIR lowering is stable on 1403 real files (14,812 functions, 0 errors, 4.6 s).
- Taint engine + 58 unit cases (Python/JS/PHP: sanitizers, branches, kill-on-reassign, loops,
  hop counting) pass; rule harness runs `kind: taint` rules with `# vuln:` annotations.
- Real code: Juice Shop → 6 `tjs-sqli` hits, incl. the real `routes/login.ts` and
  `routes/search.ts` injections; django.nV → 1 `tpy-sqli`. No false positives seen on these.
  NodeGoat/DVWA → 0 (flows cross functions/files or use sources not yet modelled: WP-5.4/5.5/5.7).
- Scan overhead: Juice Shop 12 s total (mostly parsing + existing rules), no per-file timeouts.

## Decision

Continue in-house through WP-5.4 (function summaries) and re-evaluate at the M2 gate (WP-5.9):
if inter-file recall on NodeGoat/Juice Shop stays below the gate after 5.5, add an optional
Semgrep backend behind the same rule schema instead of extending our call graph further.
Unknown calls keep propagating taint but add an `unresolved` hop, so recall gaps degrade
confidence rather than silently dropping flows.
